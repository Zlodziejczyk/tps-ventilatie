# Quick Task 260812-311 — Summary

Replaced the create-next-app default favicon with the TPS brand emblem.

## What was wrong

`app/favicon.ico` carried the same `Mar 23 14:48` timestamp as `next.svg`,
`vercel.svg`, `file.svg`, `globe.svg`, and `window.svg` — untouched scaffold.
The live site served it (`/favicon.ico` → 200, `image/vnd.microsoft.icon`,
25931 bytes), so tabs showed the Next.js mark.

## Approach

Owner chose: keep the emblem, drop the `KLIMAATTECHNIEK` sub-wordmark.

That line sits *inside* the emblem, so cropping cannot remove it, and this
machine has no ImageMagick — only `sips`, which cannot paint regions. Solved
with a dependency-free Node PNG decode/encode (`node:zlib` only): inflate,
un-filter scanlines, edit pixels, re-deflate.

The wordmark band was **measured, not guessed**. Profiling the ring interior
(x 330–1250) by per-row dark-pixel *segment* count cleanly separates lettering
from the solid ring arc:

| y range | segments/row | what |
|---|---|---|
| 396–645 | ~3 | `TPS` lettering |
| 646–675 | 0 | gutter |
| **676–727** | **20–23** | **`KLIMAATTECHNIEK`** |
| 728+ | 1–3 | ring arc only |

Painted x 360–1215, y 668–733 — inside both gutters, clear of the `TPS`
baseline (645) and the flame (starts ~776).

Then: re-measure emblem bbox (x 34–1306, y 39–1059) → centre on a 1374×1374
square with ~4% breathing room → flood-fill from the border across near-white
pixels so the *outside* of the ring goes transparent and the icon reads as a
disc rather than a white tile.

That fill is only safe if the ring is closed, so the script asserts the centre
pixel is still opaque afterwards. It passed — 75.3% of the canvas filled, ring
interior intact.

## Output

| File | Source | Size | Rationale |
|---|---|---|---|
| `app/icon.png` | disc | 256×256, 54 KB | Next.js emits `<link rel="icon">`; browsers downscale better than a hand-made 32px. 512 was 167 KB — not worth it. |
| `app/apple-icon.png` | **opaque** | 180×180, 35 KB | iOS ignores alpha and composites on black; a transparent disc would show black corners. |
| `app/favicon.ico` | disc | 16+32+48, 7 KB | Legacy + bare `/favicon.ico` requests. PNG-compressed entries, universal since IE11. |

ICO structure validated by parsing it back: `type=1`, `count=3`, every entry a
real PNG blob at its declared offset.

## Honest caveat

At 32px the full emblem is legible but soft — ring, snowflake, and lettering
start to blend. That is inherent to reducing a detailed three-element mark to
32 pixels, not a defect in the pipeline. If it reads poorly in a real tab, the
fallback is a simplified mark (ring + snowflake + flame, no lettering), which
was offered and not chosen.

Not visually confirmed in a browser — the local build deadlocks on the OneDrive
mount. Confirm on the Vercel preview.
