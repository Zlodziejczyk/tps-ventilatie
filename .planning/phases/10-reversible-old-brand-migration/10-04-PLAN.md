## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| owner's machine → the old LiteSpeed box | an `/etc/hosts` override is invisible local state that will confuse whoever finds it later; it must be documented and removable |
| our session → Thomas | every ask costs his time and can only be spent once; batching the wrong asks together wastes the reply |
| site copy → the public | the footer line is permanent, unconditional and indexed; it is the entity signal, so it must be exact and owner-approved |
| TLS certificate → the rollback trigger | D-10 treats a missing or invalid certificate as a revert signal; any `-k` anywhere would silence it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-rollback-target | Tampering | WordPress `siteurl` | mitigate | the hosts override leaves `siteurl` untouched, so a rollback stays a pure two-record DNS revert with no WordPress-side undo (D-21) |
| T-10-mig04-half-true | Repudiation | MIG-04 | mitigate | both halves required: an automated `curl --resolve` proof **and** Thomas's dated confirmation recorded as an artefact (D-22) |
| T-10-mail-tls | DoS | `mail.tpsventilatie.nl` shared-SAN certificate | mitigate | prevention via the cyberfolks question (this plan); detection via the dated `openssl` check in plan 10-10; fallback `s161.cyber-folks.pl` documented in §8/§9. Never rollback — the date may fall after the revert window closes |
| T-10-insecure-probe | Spoofing | verification commands | mitigate | no `curl -k` / `--insecure` anywhere in this phase; asserted by a runbook source check |
| T-10-hosts-orphan | Tampering | `/etc/hosts` on owner and dev machines | accept | documented in runbook §9 with a "remove this line when you no longer need WP-admin" note; the residual risk is a stale local override, which is visible and harmless |
| T-10-SC | Tampering | npm/pip/cargo installs | mitigate | no packages added by this plan |
