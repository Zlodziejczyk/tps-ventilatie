<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| probe → the thing it checks | if the probe derived its expectations from anything but the map itself, it would agree with any bug; if it derived them from a second list, it would agree with a stale one |
| Vercel edge → spoofed `Host` header | the pre-flight deliberately sends a header no real client will send until DNS moves; the platform's anti-domain-fronting response must be diagnosed, not mistaken for a broken map |
| GitHub Actions → repo issues | the new step shares the existing least-privilege token and the single alert path |
| TLS certificate → assertion validity | the certificate is a rollback trigger; a probe that skipped verification would silence it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-two-hop | Tampering | trailing-slash ordering on the legacy hosts | mitigate | the probe asserts `301` specifically and probes a slash-less source as a mandatory canary; a 308 is a named, diagnosed failure |
| T-10-silent-host | Spoofing | the request layer | mitigate | `curl` rather than Node `fetch`, because `fetch` was measured silently discarding the `Host` header — a green result about the wrong hostname is worse than a red one |
| T-10-expected-red | Repudiation | the CI step | mitigate | gated in the script on `LEGACY_CUTOVER_DATE` with a printed skip; no `continue-on-error`; green from merge, assertive from the flip |
| T-10-mail-tls | DoS | TLS verification | mitigate | no `-k` / `--insecure` anywhere; asserted by a source check |
| T-10-alert-sprawl | DoS | issue noise | mitigate | one workflow, one job, one `probe-output.txt`, one `indexation-alert` label |
| T-10-SC | Tampering | npm/pip/cargo installs | mitigate | no packages added; `curl`, `tsx` and Node builtins only |
</threat_model>
