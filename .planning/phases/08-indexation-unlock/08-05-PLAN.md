  <action>
    Create `scripts/verify-indexation.ts`, a `tsx` CLI taking one argument: the base URL to probe
    (`npx tsx scripts/verify-indexation.ts https://…`). Exit non-zero with a usage message when the argument
    is missing. Import `INDEXABLE_FLOOR` from `@/lib/seo/invariants` — do NOT import `PAGES`, `sitemapEntries`
    or any taxonomy helper, and do NOT recompute the expected count: the probe must check the deployment
    independently, sharing only the definition of "complete" (D-25).

    Steps:
    1. `GET {base}/sitemap.xml`. Assert 200 and `content-type` is XML. Parse `<loc>` values with a simple
       regex (no XML dependency). Assert the count EQUALS `INDEXABLE_FLOOR`, and assert there are no duplicates.
    2. For every `<loc>`, map it onto the base being probed (a preview deployment emits canonical-origin URLs
       in its sitemap, so rewrite the origin to `{base}` before fetching — otherwise the probe silently tests
       production while claiming to test the preview; state this in a comment, it is the subtlest trap here).
       Fetch each with `{ redirect: "manual" }` and assert the status is a DIRECT 200 — any 3xx is a violation
       reported with its `location` header.
    3. On each response body assert there is no `noindex` directive: match a `<meta name="robots" …>` tag whose
       content contains `noindex` (case-insensitive), and also catch a bare `noindex` inside an `X-Robots-Tag`
       response header.
    4. On each response body extract `<link rel="canonical" href="…">` and assert its PATH equals the path of
       the URL just fetched. Compare paths, not full URLs — on a preview the canonical legitimately points at
       `CANONICAL_ORIGIN`, and comparing hosts would false-fail every preview run.

    Run the per-URL fetches with bounded concurrency (about 6 at a time) so 27 URLs finish in seconds without
    hammering the deployment. Collect EVERY violation and print them all before exiting — a probe that stops
    at the first failure makes a broken deploy take four runs to diagnose. On success print a one-line summary
    naming the base URL and the counts checked.

    Add a header comment: what it asserts, that it is run manually at two gates (D-23) because no CI exists on
    this repo, that automating it post-deploy belongs to Phase 9, and that the no-redirect + self-canonical
    checks are deliberately included because Phase 10's migration needs exactly that checklist.
  </action>

| Boundary | Description |
|----------|-------------|
| build output → served output | A green build has already shipped visibly wrong output on this project; the deployment is the only authority on what Google sees |
| probe → the thing it checks | If the probe derived its expectation from the same taxonomy it validates, it would agree with any bug |
| branch → production | `main` deploys straight to production with no CI and no staging; the merge is the point of no easy return |

| T-8-selfagree | Repudiation | A probe that shares the source it checks | mitigate (this plan) | The probe imports only `INDEXABLE_FLOOR`; importing registry/policy is asserted against |
