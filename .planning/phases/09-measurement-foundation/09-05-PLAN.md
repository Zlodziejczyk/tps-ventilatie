## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions (public repo) → repo contents and issues | the workflow token can write; scope it explicitly |
| Vercel GitHub app → `deployment_status` events | third-party events drive the probe; gate to Production success only |
| Actions logs (public) → secret material | only the exact secret value is masked |
| `main` → production | the merge in Task 1 deploys; the preview gate must already be green |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-9-actions-perms | Elevation | `GITHUB_TOKEN` | mitigate | explicit `permissions:` per workflow; `contents: read` on the probe workflow; repo default stays read |
| T-9-recursion | DoS | bot push | mitigate | documented `GITHUB_TOKEN` no-recursion rule; `concurrency` group; commit only when staged |
| T-9-issue-spam | DoS | alert issues | mitigate | one open labelled issue, comment when it exists; simulated issue closed in-plan |
| T-9-secret-in-logs | Information disclosure | measure output | mitigate | script never prints token material (09-04 verify); workflow never echoes env; body-file is the script's own output |
| T-9-wronghost | Spoofing | probe target | mitigate | `CANONICAL_ORIGIN` derived with tsx; `environment_url` forbidden by verify |
| T-9-fork | Elevation | untrusted events | mitigate | no `pull_request_target`; `deployment_status` gated to `Production` + `success` |
| T-9-SC | Tampering | actions supply chain | mitigate | GitHub-owned actions pinned to `@v7`; no new npm packages |
</threat_model>
